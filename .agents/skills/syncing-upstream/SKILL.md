# Syncing upstream

## Layout

- `origin/main` is an untouched copy of upstream Tinycast (`abue-ammar/tinycast`). Never commit to it or push to it.
- `nanocast` is the fork and the default branch on GitHub. Its history is the upstream commits, then one snapshot commit `Rename upstream <sha> to Nanocast`, then the fork commits: one `build:` commit, then one `feat` commit for each fork feature.
- The snapshot is `origin/main` after `Scripts/rename-upstream.sh`: every Tinycast name, path and bundle id becomes Nanocast. Links to `abue-ammar/tinycast` and `tinycast.dev` keep pointing upstream.
- `Scripts/sync-upstream.sh` builds a new snapshot from `origin/main` and rebases the fork commits from the old snapshot onto it.
- During the rebase, `--ours` is the new upstream snapshot and `--theirs` is the fork commit being replayed.
- `Scripts/port-upstream.sh` resolves the conflicts of one stopped rebase step. See step 4.

Fork identity lives in these files, and the fork's values in them win: `.github/workflows/release.yml`, `Scripts/release-notes.sh`, `Nanocast/Features/Updates/Model/ReleaseFeed.swift`, the links in `Nanocast/Windows/About/AboutView.swift`, the Changelog link in `Nanocast/Palette/RootPaletteView.swift`, `README.md`, `LICENSE`, `NOTICE.md` and `SECURITY.md`.

## Steps

1. Check the start state.
   - `git branch --show-current` prints `nanocast`, and `git status --short` prints nothing. If not, stop and report.
   - `command -v xcodegen` finds the tool. If not, stop and ask the human to install it.

   Done when both checks pass.

2. Run `./Scripts/sync-upstream.sh` and record the `Old snapshot:` and `New snapshot:` lines.
   - If it prints `Already on upstream`, ask the human to sync `main` with upstream (`gh repo sync polo871209/nanocast --branch main`), then stop. Do not sync `main`.
   - Otherwise go to step 3, whether the rebase finished or stopped on a conflict.

3. Classify every upstream commit as kept or dropped.
   - List them with `git log --reverse --format='%h %s' <old snapshot>^..<new snapshot>^`, and read each one with `git show --stat --format= <sha>`.
   - Drop a commit if its subject names a removed feature, or if every path it changes outside `docs/`, `website/`, `Tests/` and the Xcode project is in the removed-features table. A commit that builds on a removed feature is dropped even when it also edits shared files, for example a launcher section that shows Quicklinks.
   - Keep every other commit. A kept commit that also touches a removed feature stays kept, and step 5 deletes those hunks.

   Done when every commit has a label and the kept list is written down oldest first. If the rebase finished in step 2, go to step 5.

4. Resolve the stopped rebase step. Repeat this step for each fork commit that stops.
   1. Run `./Scripts/port-upstream.sh <kept sha>...`. For each conflicted path it prints one line:
      - `deleted`: the fork deleted the path. The script ran `git rm`.
      - `fork` or `fork + <shas>`: the script took the fork's version and merged each listed kept commit's change into it without a conflict. The path is staged.
      - `CONFLICT ... N left`: the merge left diff3 markers labelled `fork`, `<sha>^` and `<sha>`.
      - `skip`: the Xcode project. Apply rule 1 below.
      - `by hand`: any other state, for example upstream deleted a file the fork changed. Apply the rules below to the whole file.
   2. Resolve each `CONFLICT` hunk with the first rule that matches:
      1. `Nanocast.xcodeproj/`: resolve `project.yml` first if it also conflicts, then run `git checkout --ours Nanocast.xcodeproj && xcodegen generate && git add Nanocast.xcodeproj`.
      2. A generated file (`*.generated.swift`, `Nanocast/Resources/EmojiKeywords/`): take `--ours`. If the fork changed its generator, rerun the generator named in `AGENTS.md` instead.
      3. A hunk that touches a removed feature's hooks: keep the fork side.
      4. The current fork commit replaces the feature in the replaced-features table: keep the fork side, then delete the upstream pieces listed in that table that lost their last caller.
      5. The `fork` side differs from `<sha>^` only because the fork deleted comment lines or reformatted: take the `<sha>` side without the lines the fork deleted. Most conflicts are this case, because the fork deleted most comments and reformatted with swift-format.
      6. Anything else: adopt upstream's change, then reapply the fork commit's intent on top of it.
   3. Make sure that no earlier resolution was lost. The script starts from the fork commit's original file, so an edit that an earlier rebase step made beyond upstream's change, such as deleting a dead helper, is gone again. Read `git diff HEAD -- <path>` for every path the script touched and restore such edits.
   4. Make sure that `git diff --check` reports no conflict markers, run `xcodegen generate`, and build the Debug configuration. If the build fails, fix it with the rules above.
   5. Run `git add -A` and `GIT_EDITOR=true git rebase --continue`. Run `git rebase --skip` only when git reports that the commit became empty. Ask before `git rebase --abort`.

   Done when `git status` reports no rebase in progress.

5. Sweep for removed features that arrived without a conflict. Git applies upstream edits to files the fork never touched without stopping.
   - Run `git diff --name-status <old snapshot> <new snapshot>`. Delete every added path that matches the removed-features table, and revert every change to such a path.
   - Run `git grep -n -E 'SupportCoordinator|SupportReminder|supportReminders|CommandID\.support|tinycast\.dev|discord\.gg|polar\.sh|iabueammar|coderabbit|AIChat|QuickAI|QuickAction|quickAction|aiEnabled|AISettings|AppleIntelligence|MCP[A-Z]|mcpEnabled|Features/(AI|Extensions|MCP|QuickActions|Dictation|TextInjection)|Dictation(Coordinator|Model|Helper|AudioDucker)|dictation(Enabled|Mode|Model)|HotKeyAction\.dictation|TextInjector|InjectableTextView|isInsertingText|NSMicrophoneUsageDescription|device\.audio-input|benchmark-dictation|Extension(Coordinator|Manager|CommandScreen)|extensionsEnabled|RaycastRuntime|raycast-runtime|KeychainSecretStore|allow-jit|JavaScriptCore|Colors\.Syntax|codeBlock 14|Radius\.codeBlock|syntax-highlight|`Lexer`|Quicklink|quicklink|Snippet|snippet|AppleShortcut|appleShortcut|FallbackStore|FallbackCoordinator|Fallback\.|SettingsTab\.fallbacks|CalendarStore|String\(localized|LocalizedStringResource|xcstrings|Migrations/|check-migrations|CalendarCoordinator|CalendarAccess|calendarEnabled|Meeting|EventKit|NSCalendars|personal-information\.calendars|runShellCommand|gitlab' -- . ':!.agents' ':!Scripts/rename-upstream.sh' ':!Scripts/verify-signature.sh' ':!docs/features/calculator.md' ':!AGENTS.md' ':!docs/standards.md'` and remove each hit.
   - Run `xcodegen generate` so the project drops the deleted files.

   Done when the grep prints nothing and no path from the diff matches the table.

6. Verify.
   - `xcodegen generate` leaves `Nanocast.xcodeproj` unchanged in `git status`.
   - `xcodebuild -project Nanocast.xcodeproj -scheme Nanocast -configuration Debug -derivedDataPath build/DerivedData build` prints `BUILD SUCCEEDED` with no new warnings. If the `Nanocast Self-Signed` identity is missing, add `CODE_SIGNING_ALLOWED=NO`.
   - `./Scripts/run-tests.sh` passes, `./Scripts/lint.sh` is clean and `node Scripts/check-settings-search.js` passes.
   - `grep -rln 'import AppKit\|import SwiftUI\|import Cocoa' Nanocast/Features/*/Model/` prints nothing.
   - Both `@Observable` counts in `docs/architecture.md` equal `git grep -h '@Observable' -- 'Nanocast/*.swift' | grep -vc '^ *//'`.

   If a check fails because of the sync, fix it and decide with the rules in step 4. `settings-backup-test` and `settings-file-test` pin every persisted settings spelling. If one fails on a key that upstream added, add the key to the test's list. Done when every check passes.

7. Fold everything that is not a fork feature into the fork commit it belongs to. Do not add separate commits and do not push.
   - Commit each step 5 and step 6 fix with `git commit --fixup=<fork commit>`. A removed-feature sweep belongs to the `build:` commit. A fix to a fork feature belongs to that feature's commit.
   - Fold every `github-actions[bot]` commit into the `build:` commit. `release.yml` adds one per release, with the subject `nanocast <version>`, to bump `Casks/nanocast.rb`. Do not drop it. This repo is its own Homebrew tap, and without the bump the cask goes back to version `0.0.0` with a zero `sha256`.
   - Fold every other fork commit that adds no feature, such as a `fix`, `docs`, `chore` or `refactor` commit, into the commit whose code it changes. Keep each `feat` commit separate.
   - To fold an existing commit, move its line in the `git rebase -i <new snapshot>` todo list below the target commit and change `pick` to `fixup`.
   - Run `GIT_SEQUENCE_EDITOR=true git rebase -i --autosquash <new snapshot>`.

   Done when `git status --short` prints nothing, and `git log --format='%an %s' <new snapshot>..` lists the `build:` commit and the `feat` commits, with no `github-actions[bot]` author.

8. Report, then stop.
   - The upstream commits, each with its step 3 label.
   - Each `CONFLICT` and `by hand` path: the rule from step 4 and one line on the result.
   - Each upstream piece deleted under the replaced-features table, with its path.
   - The verification results and which fork commit each fix was folded into.
   - The command for after the human's review: `git push --force-with-lease origin nanocast`.
